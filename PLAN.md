# Project Overview: Land Stack (SIH26014 - Dept of Land Resources)

**Context:** We are building a unified GIS-based Digital Public Infrastructure platform. The goal is to solve the fragmentation of land records in India by linking all departmental data (revenue, registration, taxation, utilities) to a single unique identifier: the ULPIN (Bhu-Aadhaar). 

**Tech Stack:** 
- Frontend: Next.js (React), Tailwind CSS, Leaflet or Mapbox GL JS (for mapping), Recharts (for charts).
- Backend: FastAPI (Python), PostgreSQL + PostGIS (for spatial data and ULPIN linking).
- Deployment focus: Local Docker Compose for demo, easily translatable to scalable architecture.

## 1. Core UI Architecture
The application layout follows a robust admin-dashboard structure.
- **Left Sidebar (Navigation):** Map View, Data Analytics (City Overview), Workflow/Requests, Admin Settings.
- **Top Navigation Bar:** Global Search (Autocomplete supporting ULPIN, Plot Number, Owner Name, Address), and global KPI cards (Total Revenue, Active Utilities, Registered Parcels, Active Alerts).
- **Main Content Area:** Interactive Map (default view) or Analytics Dashboards (depending on sidebar selection).
- **Right Sidebar (Plot Profile):** Contextual side-panel that slides in when a parcel is clicked on the map or searched.

## 2. Interactive Map & Layering System
The map must be highly interactive and performant.
- **Base Map Options:** Toggle between Satellite and Street views, with 2D/3D toggle capabilities.
- **Vector Polygons:** Render land parcels accurately using GeoJSON/Vector Tiles from PostGIS.
- **Interactive Clicking:** Clicking a polygon highlights the parcel border (e.g., blue outline) and instantly opens the "Plot Profile" in the right sidebar.
- **Layer Control Overlay (Bottom Left):** Toggleable data overlays including:
  - Water Lines
  - Power Grid
  - Tax Defaulters Heatmap
  - Zoning Restrictions

## 3. Data Requirements (The "Plot Profile" Right Sidebar)
When a parcel is selected, the system must fetch and display unified data linked to that ULPIN:
- **Header:** Plot Number, ULPIN/Bhu-Aadhaar, Map Thumbnail, Action Buttons (Issue Notice, Print Profile, Request Verification).
- **Land Ownership (Record of Rights):** Owner Name, Ownership Type (Freehold/Leasehold), Plot Size, Land Use (Zoning), and an expandable "Previous Land Deed" history log.
- **Fiscal Status (Tax Department):** Property Tax Status (Paid/Defaulter), Current FY Due, Arrears, and a small 5-year payment history sparkline/chart.
- **Utilities (Electricity & Water):** Connection Status (Active/Inactive), Provider, Connection ID, Avg. Consumption, Meter Status, Recent Bill Amount.
- **Physical Assets & Infrastructure:** Sewage Connection Status, Nearest Manhole ID, Building Plan Approved Status (e.g., G+3), and Active Violations Flagged.

## 4. City-Wide Analytics Dashboard (Macro View)
When navigating to the "Data Analytics" tab, the system must display aggregated data:
- **City Overview:** Total Area, Population Demographics, Total Registered ULPINs vs Municipal Wards.
- **Civic Infrastructure:** Lists of Service Buildings (Schools, Hospitals) with operational statuses.
- **Revenue & Collection Metrics:** Grid of collection data for Sewer, Water, Electricity, Property Tax, and Garbage. Must include percentage collection bars, total dues, and actionable "View Defaulters" links that route back to the map.

## 5. New Features to Implement (The "Winning Edge")
Please implement these advanced features to differentiate the platform:
- **Spatial Query Tool (Draw & Select):** Allow users to draw a polygon on the map to select multiple parcels and instantly calculate aggregated data (e.g., "Total pending property tax in this drawn area").
- **Automated Conflict Engine:** A background process that checks for discrepancies across departments (e.g., Zoning = Residential, but Utility Consumption = Industrial). Display these as "Active Alerts" in the top bar and flag them in red on the Plot Profile.
- **Time-Slider for Ownership History:** A UI component that allows an officer to drag a slider back in time to visually see how a plot was subdivided or changed ownership over the decades.

## 6. Hidden Problems & Architectural Constraints to Handle
**AI Assistant, you must account for the following technical hurdles while generating code:**
1. **Map Rendering Bottleneck:** Rendering thousands of GeoJSON polygons on the Next.js client will crash the browser. You must structure the map component to consume Vector Tiles (MVT) generated by PostGIS, not raw GeoJSON, for bulk data.
2. **Asynchronous Cross-Department Fetching:** Assume the external departmental APIs are slow. The `Plot Profile` right sidebar must use skeleton loaders for each section (Tax, Utilities, Ownership) independently so the UI doesn't freeze while waiting for one slow department database.
3. **Complex State Management:** Ensure seamless state synchronization between the Map bounding box, the Layer toggles, and the active ULPIN selected in the sidebar without causing infinite React re-renders.
4. **Fuzzy Search Indexing:** Legacy data is messy. The search bar must tolerate typos and partial matches for owner names or addresses using a robust search index (e.g., PostgreSQL `pg_trgm`), not just exact matches.
